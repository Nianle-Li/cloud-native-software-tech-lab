# 前端创建场地：实现与验证记录

检查日期：2026-10-29；工作分支：`feature/frontend`。

## 需求依据与范围

已读取本地《云原生软件技术-Lab1-场地预约系统开发与Docker容器化.pdf》全文。第 3 页第 2.3 节把“创建场地”列为系统必做功能；第 5 页规定前端通过 HTTP API 操作、显示成功与失败信息。根据本次前端补齐要求，增加可操作的创建场地页面。字段、格式与接口沿用现有公共契约和后端实现，无需修改后端或数据库结构。

原实现已有 `CreateVenueInput`、`bookingApi.createVenue`、`validateVenue` 和 `#/venues/new` 路由解析，但没有页面渲染、入口、表单、写入后的状态更新及本地模拟接口。

## 实际验证结果

按测试驱动方式执行：

1. 修改前运行全部测试：9 个文件、63 项通过。
2. 先加入创建流程和模拟接口测试：35 项新增测试失败，复现页面与接口缺失；该轮已有的 2 项模拟预约测试通过。
3. 实现后相关 37 项测试通过。全量回归：10 个文件、98 项通过。
4. 复查时补充“首次列表晚到后仍显示已有场地”的断言，先观察到失败，再修正列表合并逻辑。两项竞态测试通过，最终全量 98 项测试再次通过。
5. 最终 `npm run build` 通过 TypeScript 检查并生成生产构建。顺带修正已有 `api/booking.test.ts` 的场地输入类型声明，避免 `status` 被推断为普通字符串而阻断构建。

复现自动检查，在 `frontend/` 使用 Node.js 24.15.0：

```sh
npm ci
npm test
npm run build
```

另使用 Chromium 141.0.7390.37，通过实际 Vite HTTP 代理连接本地模拟 API，完成：空白名称不发送创建请求；有效创建返回 201；成功后清空表单；刷新列表及浏览器后仍可查询；新场地预约与取消；停用场地不可预约；首次列表响应延迟到创建之后，已有与新建场地均保留。检查过程中未发现浏览器运行错误。

四个视图在 375、800、1024、1366、1920 像素宽度下的 20 组布局检查通过，未发现文档横向溢出、导航或表单控件越界；另已查看创建页的移动端与桌面端截图。手动复查步骤见 [README](../README.md#使用模拟-api-手动检查前端交互)。

以上仅是前端、模拟 API、类型与构建验证。未执行真实后端 HTTP、数据库持久化或 Docker 三服务联调，不能据此把这些验收项记为通过。
