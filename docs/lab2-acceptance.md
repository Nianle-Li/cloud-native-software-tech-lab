# Lab 2 验收与报告记录清单

本清单用于实施和报告时逐项核对；当前各项均为**待验证**，不代表已经完成。需求与方案见 [Lab 2 契约](lab2-contract.md)，跨成员接口与确定的设计选择见[公共契约](lab2-shared-contract.md)。实际命令需带正确的 kubeconfig 与命名空间；以下以 `venue-booking` 为目标命名空间。

| 验收项 | 操作与应保留的证据 | 通过条件 |
| --- | --- | --- |
| 环境 | 记录 `kubectl version`、`kubectl get nodes -o wide`、镜像构建/加载命令 | 版本、节点数、镜像来源可复现 |
| 公共契约 | 记录集群、镜像/存储的实测适配值，并核对同窗口快照、异常终态、探针和测试数据批次 | 三人使用同一资源名、字段、命令和数据口径；实施与已定契约一致 |
| 清单 | 分别校验 `k8s/base/` 中的常规资源、`k8s/jobs/` 中生成的手动 Job 和 `k8s/demo/` 中的临时覆盖清单；按 README 的依赖顺序部署，演示覆盖只在演示时应用；部署后 `kubectl -n venue-booking get deploy,sts,ds,job,cronjob,svc,cm,secret,pvc,pods -o wide` | 清单有效、资源类型齐全；没有因整体应用 `k8s/` 而误启动任务；敏感值不出现在提交文件与报告中 |
| 健康与发现 | `kubectl -n venue-booking get endpointslice`、`kubectl -n venue-booking rollout status deployment/api`，前端页面请求 `/api/venues` | 前端经 Service 到 API；API 经 Service 到数据库，Pod 均就绪 |
| 业务回归 | 在 Kubernetes 入口逐项执行场地列表/详情/创建，预约创建、冲突、列表/详情、取消 | 与 Lab 1 业务规则和错误码一致；无 Pod IP 依赖 |
| 浏览器端到端回归 | 对真实集群的前端入口运行可重复的浏览器流程；记录镜像版本、测试数据及失败截图/日志 | 场地、预约、冲突、取消和报告查询可通过页面完成；模拟响应测试与真实集群结果分别标注 |
| 数据保留 | 创建场地和预约，记录 ID；删除数据库 Pod，待 StatefulSet 恢复后再次查询 | 原 ID、状态和数据仍在；PVC 保持 Bound |
| API 扩展 | 确认 2 个就绪 API Pod；经 `api` Service 用独立连接多次请求 `/api/instance`，保存响应和 Pod 日志 | 至少出现 2 个不同 `instance_id`；同一时段并发预约仍只允许一个成功 |
| 一次性报告 | 用指定起止日期创建唯一 Job，查 Job 状态、日志和 `/api/reports/{job_id}`；核对数据库原始记录；同 ID 重试与不同 ID 同窗口分别验证 | 每个场地含零值行；仅有效预约计数与分钟数正确；同 ID 无重复明细，不同 ID 保留独立快照；成功/可捕获失败可追踪，Pod 删除后仍可查询 |
| 报告页面 | 从手动触发命令或 Job 列表取得 ID，在 `#/reports` 输入并同页查询；分别模拟/实测运行中、成功、失败、404、断网与异常响应，并覆盖长时间未变化的 `RUNNING` | 展示状态、范围与零值明细；可手动刷新，对可能继续重试或过期的状态给出准确提示；页面无 Kubernetes 管理权限 |
| 定时报告 | 通过 API 创建当天有效预约与零值场地；将同名 CronJob 临时改为每 2 分钟、`TODAY` 模式，观察至少两次 Job 并核对 `job_id`、日期、非零/零值结果；验收后恢复每日 00:10、`PREVIOUS_DAY` 模式，检查 `Forbid`、时区、调度期限与 Job 重试/截止参数 | 自动触发且结果可由当日业务数据验证；演示与正式模式分别留证；同窗口多快照与重叠处理符合契约 |
| 节点任务 | `kubectl -n venue-booking get ds,pods -o wide`，对照可调度节点和各 Pod 日志 | 每个符合条件的节点一个运行中 Pod；日志对应节点名、宿主 IP 和集群 DNS 检查结果 |
| 报告 | 架构图、资源用途/选择理由表、主要用例、三类任务证据、配置与存储、副本策略、小组分工和问题解决 | 图、表、命令、截图、数据对应实际运行；按任务书截止日期提交 |

记录失败项时保留真实错误、修复和重测结果。集群没有 StorageClass、节点不足、镜像不能装载或资源不足时，先记录环境事实，再调整部署方案与契约；不得将未执行的检查标记为通过。
