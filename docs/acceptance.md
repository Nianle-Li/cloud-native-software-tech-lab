## 1. 功能与错误

| 检查 | 合格结果 |
|---|---|
| 场地 API | 创建、列表、详情均可用，数据真实写入数据库；前端可创建场地、展示列表和详情，停用场地不可预约 |
| 预约基本流程 | 前端创建预约、显示成功信息、查看预约列表和详情、取消预约 |
| 冲突与释放 | 同场地同日期时段重叠返回 `409`；相邻时段可预约；取消后原时段可重新预约，旧记录仍显示 `CANCELLED` |
| 输入和不存在资源 | 必填字段、日期/时间、开放时段、人数、停用场地得到明确错误；不存在 ID 返回 `404`；无异常堆栈暴露 |
| 并发冲突 | 同场地同日期同时段并发提交两次，只有一条有效预约成功，另一条返回 `409` |

```text

```

检查 `frontend`、`api`、`database` 三个服务正常；前端能访问 API，API 能通过 `database:5432` 访问 PostgreSQL，数据库 healthcheck 正常，日志中没有持续重复的严重错误；只有确需从宿主机访问的端口被发布。前后端镜像必须能由各自 Dockerfile 从源码构建，镜像中不包含真实密钥。

持久化验证须记录预约 ID，按下列顺序操作，并在重新启动后查询同一 ID：

```text
docker compose down
docker compose up -d
docker volume ls
```

预约仍存在、项目数据库 volume 可见才算通过。`down` 不加 `-v`。仓库应有 `.env.example`；真实 `.env` 必须被 `.gitignore` 忽略，不提交真实账号、密码、Token 或密钥。启动命令、访问地址和环境变量应写入 README，让其他人能够从干净环境复现。

### 第 4 阶段复现方式

Docker 引擎运行且 Python 3.9 或更新版本可用时，在仓库根目录执行：

```sh
python3 scripts/verify-database.py
```

Windows 可使用 `python scripts/verify-database.py`。脚本创建独立的 `lab1-db-check-<随机后缀>` Compose 项目，只启动当前 `compose.yaml` 的 `database` 服务；使用临时配置及随机密码，不创建根目录 `.env`，不依赖 B 的 API 或 Dockerfile。

验证工具使用 `redgate/flyway:11.20.0`，依据[官方镜像说明](https://hub.docker.com/r/redgate/flyway)将仓库迁移目录只读挂载到 `/flyway/sql`；该工具镜像通过 `linux/amd64` 运行，ARM Mac 需要 Docker Desktop 支持模拟。该版本仅用于独立验证，不替代 B 最终选定的应用 Flyway 版本，也不增加生产 Compose 服务。

脚本检查数据库健康、端口未发布、V1/V2 迁移历史、种子数量和冲突索引，然后运行 Flyway `validate` 和第二次 `migrate`，确认历史与种子数量不变。数据约束验证包含无效输入的预期 SQLSTATE 类别检查，以及合法插入、默认值、文本长度边界、逻辑取消和外键删除保护。

约束验证在事务中回滚，保留三条场地种子且不保留测试预约；identity 序列可能因测试取号而前进。脚本结束时执行 `down`，不加 `-v`，并输出保留的独立验证卷名。该验证不计作第 6 阶段的预约重启持久化验收。

### 第 4 阶段实际结果

执行命令：`python3 scripts/verify-database.py`；退出码为 `0`。环境为 Docker Engine 29.2.1、Compose v5.1.0，PostgreSQL 实际版本为 `16.15 (Debian 16.15-1.pgdg12+2)`，独立迁移工具为 Flyway Community Edition 11.20.0。

| 实际检查 | 结果 |
|---|---|
| 数据库启动 | Compose 等待健康检查通过，容器状态为 `healthy`；未发布宿主机端口 |
| 首次迁移 | 从空库成功应用 V1、V2，迁移历史两条均成功，当前版本为 2 |
| 场地种子与索引 | 场地共 3 条，其中 OPEN 2 条、CLOSED 1 条；预约 0 条；冲突查询索引存在 |
| 校验与再次迁移 | Flyway `validate` 成功；第二次 `migrate` 返回无需迁移，历史版本、校验和及种子数量不变 |
| 21 组非法写入 | 场地/预约必填列、四种文本的空白与超长、无效外键、非正人数、相等/倒序时间、非法状态及取消时间不一致均按预期 SQLSTATE 类别拒绝 |
