## 模糊条款与用户决策

任务书第 3 页要求**系统**支持场地和预约详情查询，第 5 页的前端最低交互仅写查看场地基本信息和展示预约记录。仓库已有的分工与验收文档将前端详情列为目标。用户已确认采用保守解释：新增两个独立详情页，并让预约记录同时显示场地名称与编号。详情页使用实际详情 API，而不是仅复用列表中的对象。

任务书对登录、权限、场地编辑、预约改期和物理删除没有要求；当前公共契约也未开放这些能力，不列为本阶段前端遗漏。

## 验证范围

详情页的路由、直接访问、API 响应校验、列表入口、404 反馈和刷新恢复均有自动测试。加入本轮功能后，`npm test` **11 个文件、115 项通过**，`npm run build` 和 `git diff --check` 通过。Chromium 配合本地模拟 API 验证了详情查询、创建与取消流程、停用限制、缺失编号反馈，原四视图 20 组以及新详情页 6 组宽度检查均无横向溢出或运行错误。

本轮没有运行真实 Spring Boot API、PostgreSQL、Docker 镜像或三服务 Compose；这些属于跨组件联调与持久化验收，不能由模拟 API 测试替代。
